# ACNH 绘制中清除的验证依据

第十八次实际启动在 `clear_ds_quad` 的 `TOTK_GPU_MIDCLEAR` 门禁处停止，清除尚未执行。第十九次保持保护开启，取得首次进入该路径的参数：frame105、此前通道计数273；只写深度1、模板写掩码0；768×768、NVN格式0x34精确映射 Depth32Float，样本字段0表示单采样；默认视图格式/level0/layer0，scissor为左上512×512。此时没有活动编码器，pass不是新通道号。

非启动版 ACNH 装载器只额外允许 `probe-gpu-midclear` 和 `probe-gpu-ds-clear` 两个精确参数，执行前仍校验和装载绑定的三模块，不执行 SDK Start 或游戏构造函数。正式启动版仍仅允许 `probe|boot`。Make 探针使用独立游戏槽、headless 和 Metal API Validation/assert，接线经独立复核。

在 Apple M5 Max 上，最终构建的五个独立 GPU 进程符合预期：

| 探针 | 正控 | 负控 |
| --- | --- | --- |
| 颜色 midclear | 9,216项检查通过 | 故意不写 alpha，在 `(0,0)` 检出差异并中止 |
| 深度／模板及清除后绘制 | 2,955,264项检查通过 | 扩大模板写掩码，在 `(4,8)` 检出差异并中止；保留旧剪裁，在右侧 `x=512` 检出差异并中止 |

颜色探针覆盖 RGBA8 与 RGBA16F 双颜色附件、Depth32F、部分颜色通道、scissor 和未修改区域。原深度／模板探针覆盖单采样 Depth32Float_Stencil8、活动与重开通道、部分模板写掩码、仅模板／仅深度／零掩码，以及颜色和未触及像素保持。

ACNH 专用补充探针按实际纯深度参数清除，然后在同一编码器内经生产 `OP_DRAW` 连续绘制：全屏红色深度0.9、右侧绿色深度0.7。逐像素检查左上清除区通过 LESS、左下未清除区保留原色及深度0.8、右侧恢复全幅剪裁并写入深度0.7；同时断言恰有两次生产绘制且编码器不变。新增 helper 和调用仅在 GAME_ACNH 启用。

独立复核通过，结果及二进制／日志 SHA-256 见 `work/acnh/3.0.0/analysis/gpu-clear-probes-v3.json`。负控中止是预期错误检测，不计为未解决的生产崩溃。实现中曾发现命令数组容量不足、纯深度读回选项不匹配，在 GPU 执行前修复；v2 实际运行又发现探针 MSL 输出属性语法错误，修为带颜色属性字段的返回结构后，v3 全部符合预期。失败日志仍保留，不计为通过证据。

第二十次只在该轮诊断环境设置 `TOTK_GPU_MIDCLEAR=1`，实际越过原门禁，继续着色器翻译和绘制，随后在 NIFM 命令4明确停止。默认启动配置未改。截图到第60帧均全黑，发生在首次清除之前；清除后的画面仍待捕获。

这组证据支持继续受控诊断，不覆盖全部 NVN 格式、MSAA、视图或任意游戏流程；可识别首帧、画面正确性和可玩性仍未验收。
