# ACNH Switch 版移植至 Apple 芯片 Mac / iPhone：架构判断

**范围和证据边界。** 本文比较固定提交的 [Mush8](https://github.com/c22dev/mush8/tree/975040ba341efb99c5631292a0266ae26b28d960)、[MacNativeGames](https://github.com/ly05010419/MacNativeGames/tree/dfa7ec426f8b37798073a108ede1504c827d8af0)、[D2R Mobile](https://github.com/jhaizhou-ops/d2r-mobile/tree/53e7c5bb9ca3ea53e2160005be8fbe920cd9cb53) 源码及本次三份分析报告，并纳入当前样本的只读解析和 shader 工具链采样结果。用户分别跑通三个项目，只证明本机环境可运行它们各自已支持游戏，不能推导 ACNH 的兼容率、开发成功概率或性能。ACNH 尚未运行；包容器和 ExeFS 的数据块哈希已验证，未验 RSA 签名。密钥仅在内存用于解析，没有输出或落盘。

本地 XCI 的 `control.nacp` 为 **1.0.0**、base title ID 为 `01006F8002326000`；NSP 的 `control.nacp` 为 **3.0.0**、update meta title ID 为 `01006F8002326800`。两个 ExeFS 均包含 `main`、`rtld`、`sdk`、`subsdk0`、`main.npdm`。3.0.0 四个模块均有 `DT_RELR`：展开后的重定位条目依次为 main 373,220、rtld 39、sdk 15,005、subsdk0 3,424，均落在 `.data`；RELA/JMPREL 也无 text/rodata 目标。8 个 NSO 的三段哈希复算均匹配。两版 NPDM 均表明 64 位 AArch64，3.0.0 相对 1.0.0 增列 `svcMapPhysicalMemory`/`svcUnmapPhysicalMemory` 及 `ectx:aw`、`mnpp:app`、`ngc:u`、`ngct:u`、`notif:a`、`olsc:u` 服务访问权限；**能力列表不代表实际调用**。3.0.0 的 `main` `.text` 从 base 约 35.7 MB 增至约 66.1 MB，也提示不能用旧版扫描/补丁规模外推新版。这些结果支持“可研究的 AArch64/重定位输入”判断，但尚不证明改写可行、Mac 能启动、iPhone 能装载，亦不等于更新 RomFS 已合并。详细静态证据见 [ACNH 二进制画像](acnh-binary-profile.md)。

## 建议：以 MacNativeGames 为唯一宿主基座，先做 ACNH 的 macOS 单机纵切片

前提是 ACNH 的具体 AArch64 指令、SDK/Horizon/NVN 足迹仍落在这条技术路线可扩展范围。技术路线是：离线解包并校验版本 → 对 guest AArch64 做可证明的 x18/TLS/SVC/计时等改写 → 在 Apple Silicon 上原生执行 guest 代码 → 宿主补 Horizon SVC/IPC 与文件、时间、账户等服务 → 把实际使用的 NVN 命令和 Maxwell shader 映射至 Metal。iOS 阶段预先把改写后的代码嵌入签名 Mach-O，并优先在构建机翻译、编译 shader 种子。**iOS 对 CPU 动态生成代码的签名限制，不等于禁止 Metal 在运行时编译 MSL。** Apple 提供 [`newLibraryWithSource:options:error:`](https://developer.apple.com/documentation/metal/mtldevice/makelibrary%28source%3Aoptions%3A%29?language=objc)；现有方案之所以选择离线 AOT，是因为没有在 iOS 应用中携带 C# translator，且要控制 shader miss、首遇卡顿和覆盖。它不是把 ACNH 源码重编译成常规原生 App，也不是把三套 runtime 拼接起来。

选择 MacNativeGames 的真正差异有两层。其一，**已有 TOTK→BOTW 第二个标题接入的实际工程路径**：title/version 指纹、独立构建分支、游戏补丁、ROMFS 与 shader 清单被迫区分，底层 loader、HIPC/CMIF、线程和 NVN/Metal 仍能复用。[构建路由](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/build_app.py#L1050-L1095)、[BOTW 专属补丁](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/runtime/game_patches_botw.c#L1-L23)。其二，**当前 ACNH 3.0.0 的具体格式更接近它现有工具可扩展边界**：MNG 已有有界的 [RELR 解包](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/third_party/d2r/relr.py#L1-L43) 与 [运行时重定位清单生成](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/scripts/prepare_runtime.py#L50-L79)；[Mush8 的 `nxfs` 遇 RELR 标签会拒绝](https://github.com/c22dev/mush8/blob/975040ba341efb99c5631292a0266ae26b28d960/crates/nxfs/src/module.rs#L83-L90)，须先增加该格式能力。MNG 的构建管线还把游戏输入、模块改写、资源和 shader 种子、Mac/iOS 包装连成一条可审计流程；[模块及散列门禁](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/build_app.py#L428-L468)、[iOS 签名代码段](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/ios/tools/gen_embed.py#L17-L59)。其图形后端和改写器已从 D2R 派生；再并入 D2R 的整套 runtime 会制造两套线程/内存/图形语义。[第三方来源](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/THIRD_PARTY_NOTICES.md#L1-L23)。

这仍不是“改个 title ID 就能跑”。MacNativeGames 的构建和运行时代码含大量 `TOTK_GAME_*` / `GAME_BOTW` 条件编译、固定地址与版本专属补丁；应建立 `games/acnh` 独立适配入口，在实际需要复用的底层接口上做最小抽离。[版本地址表](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/runtime/game_version.h#L1-L30)、[补丁原字节校验](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/runtime/game_patches.c#L520-L594)。ACNH 3.0.0 的 rtld/sdk/subsdk0 仅含 `DT_GNU_HASH`，不含 `DT_HASH`。MNG 的 [`prepare_modules.py`](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/scripts/prepare_modules.py#L72-L80) 和 [`prepare_runtime.py`](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/scripts/prepare_runtime.py#L50-L61) 已有从 NSO dynsym extent 推出符号数的回退，但 [`patch_nso.py` 的 call-window 安全检查](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/games/totk/third_party/d2r/patch_nso.py#L763-L781) 仍无条件访问 `tags[4]`。若 ACNH 进入该检查，会报错；需把同一有界 dynsym 计数规则接上并对需经过该路径的模块逐个验证，不能跳过符号/调用目标检查。其影响是**明确的小范围解析/校验缺口**，不是 RELR 不可用或整条路线的硬停止。固定提交的图形路径用 Metal 4，项目自述要求 macOS/iOS 26；目标设备和系统若不满足，要在方案入口更换或扩展图形后端。[平台要求](https://github.com/ly05010419/MacNativeGames/blob/dfa7ec426f8b37798073a108ede1504c827d8af0/README.md#L78-L125)。

**替代路线及切换条件。** Mush8 的 Rust `nxpatch` 在指令分类、不可安全改写时拒绝继续、Unicorn 差分等价检查方面适合用作独立核验工具/设计参照；其 `nxfs` 当前拒绝 ACNH 3.0.0 所用的 RELR 标签，且 NVN driver 表、启动模块和游戏补丁都与 MK8D 绑定，独立拿它做 ACNH 主基座需补更多底层和标题接入。[改写拒绝边界](https://github.com/c22dev/mush8/blob/975040ba341efb99c5631292a0266ae26b28d960/crates/nxpatch/src/rewrite.rs#L465-L545)、[driver 固定 module ID](https://github.com/c22dev/mush8/blob/975040ba341efb99c5631292a0266ae26b28d960/crates/nxhost/src/nvn/mod.rs#L16-L57)、[差分核验](https://github.com/c22dev/mush8/blob/975040ba341efb99c5631292a0266ae26b28d960/crates/nxpatch/src/equiv.rs#L47-L66)。D2R Mobile 的成熟 iOS 前端、后台/存档协调、图形时序与故障注入经验可定点借鉴；其游戏私有 CUTS/OBS/私有 SVC 不进 ACNH 基座。[iOS 生命周期](https://github.com/jhaizhou-ops/d2r-mobile/blob/53e7c5bb9ca3ea53e2160005be8fbe920cd9cb53/dm/ios/Sources/front_ios.m#L1143-L1185)、[D2R 专属补丁](https://github.com/jhaizhou-ops/d2r-mobile/blob/53e7c5bb9ca3ea53e2160005be8fbe920cd9cb53/dm/tools/patch_nso.py#L46-L80)。如果 ACNH 的 SDK 导出、NVN 使用范围或 shader 特征与 MacNativeGames 的宿主严重不合，先定量列出缺口，再比较转向 Mush8 图形链、针对性重做后端、或停止直接执行路线；不预设混合能解决问题。若后续证实需要无法签名的运行时 **CPU** 代码生成，则 iPhone 直接执行路线应重估；Metal MSL 源码编译不是这种障碍。

**现有 shader 样本的意义。** base 1.0.0 的 RomFS 元数据只读扫描约 66,790 个文件，`Shader/*.szs` 中含 `Park_UBER_All`、`Park_Proc`、`apkg` 等 16 个路径候选；当前解析器从三类主包读到 71/3,363/16 条记录，跨包尚未去重，亦非全游戏 shader 总数或实际运行变体数。以已 SHA-256 核验的 MacNativeGames NativeAOT `totk_xlate` 对每包每 stage 的最长/最短候选做 13 样本 smoke：12 个成功翻译成 SPIR-V/MSL，并且这 12 个在 macOS/iOS Metal 编译及 metallib 链接均通过；1 个 BAHS heuristic 提取出仅 1 byte 的顶点着色器候选，引发 `IndexOutOfRange`，需先校验候选提取规则，不能静默滤掉。这些样本使用默认绑定状态，**只证明少量 base 1.0.0 输入可过当前工具链**，不证明绑定/反射正确、画面正确、shader 全覆盖、3.0.0 更新资源可用，也不证明运行时 NVN 命令覆盖。3.0.0 RomFS 的 BKTR 更新合并尚未完成。该结果支持先做受控图形纵切片，而非提前承诺 iPhone shader AOT 已解决。

## ACNH 专属风险不能被通用启动 smoke 覆盖

1. **真实时间、季节、时区和休眠。** 官方说明游戏里的时间/季节与现实同步，物种与活动随时段变化。[Nintendo 玩法说明](https://animalcrossing.nintendo.com/new-horizons/explore/)。因此 guest 的本地/UTC 时间、单调计时、时区与夏令时、跨午夜、改系统时间、离线恢复和 iOS 入后台后的时钟行为应分开测；不能简单使用 D2R 的固定时间测试设置作为产品行为。[D2R 时间实现](https://github.com/jhaizhou-ops/d2r-mobile/blob/53e7c5bb9ca3ea53e2160005be8fbe920cd9cb53/dm/host/hle_time.c#L1-L54)。活动是否另需网络鉴权/特殊时间服务，要按 ACNH 实际调用确认。
2. **系统级岛存档与账户关系。** 官方说明一个主机是一座共享岛，多名用户各有居民；岛数据不会随普通用户存档迁移，岛代表不能单独迁走。[新游戏/账户说明](https://www.nintendo.com/en-gb/Support/Purchases-Subscriptions/Games/How-to-Start-a-New-Game-Animal-Crossing-New-Horizons--1747986.html)、[普通存档迁移例外](https://en-americas-support.nintendo.com/app/answers/detail/a_id/27394)、[岛/居民迁移](https://www.nintendo.com/au/support/articles/how-to-transfer-animal-crossing-new-horizons-save-data/)。宿主不能将“每启动用户一个独立存档目录”照搬给 ACNH；须分析其 system save 与 account save 的真实打开、commit 和用户映射。早期只用全新、可丢弃的测试岛；导入真实岛、跨设备同步和向 Switch 回写都独立立项，先建立一致性校验、快照/回滚和断电/后台中断恢复。
3. **命名和文字输入。** 官方明确人物名、岛名和生日确认后不能更改，输入使用屏幕键盘。[Nintendo 新游戏说明](https://www.nintendo.com/en-gb/Support/Purchases-Subscriptions/Games/How-to-Start-a-New-Game-Animal-Crossing-New-Horizons--1747986.html)。`swkbd` 接口要覆盖 Unicode、输入法组合、字符限制和提交/取消；错误的默认字符串会永久污染测试岛。另测菜单文字、聊天与字体回退。
4. **离线可玩与局域网不能混为一谈。** 官方列单机、同机多人、局域无线和在线为不同模式，局域游玩需多主机/多份游戏，机场流程有会话建立、加入和关闭。[Nintendo 多人说明](https://en-americas-support.nintendo.com/app/answers/detail/a_id/49136/)、[官方规格](https://www.nintendo.com/us/store/products/animal-crossing-new-horizons-switch/)。第一阶段明确只承诺单用户本机离线体验；联网相关 service 要诚实返回受限状态并验证单机流程不受阻。局域网不是“把 `bsd` socket 转 TCP”就可用：无线发现、会话身份、账户状态、同步和断线存档一致性需独立抓轨迹与协议边界评估。不要承诺与真 Switch 互通或 Nintendo Online 功能。
5. **更新和附加内容。** 现有 NACP 已确认 base 1.0.0 与 update 3.0.0。**建议把 3.0.0 锁为产品目标版本**，因为用户已有对应更新包，且 RELR 在数据段、GNU-only 缺口具体可修；先补 BKTR 合并和版本 profile。base 1.0.0 可用作差分诊断或更快的第一帧实验，但它的纵切片不算 3.0.0 验收。DLC/HHP、活动资源、字体和系统数据均可能改变文件系统及服务足迹；首次纵切片不把它们作为默认覆盖范围。版本升级须独立散列、补丁和存档兼容性检查。

| 3 iOS 移植 | 签名 Mach-O 代码段、AOT shader 集、UIKit 输入、系统键盘、前后台时钟/音频/存档、热量/内存画像 | 指定设备和 OS 上**首次全新安装启动**、命名和读写档、前后台/锁屏/来电中断、长期游玩与设备资源测试通过；第二次启动不代替首次门禁 |
| 4 可选扩展 | 多账户/同岛多人、DLC、局域通信、原岛导入与版本更新逐项立项 | 每项有独立接口轨迹、存档一致性和真机端到端验收；不因主线可玩而自动宣称完成 |

阶段 0 不应为一个孤立的“技术报告”拖很久：只读盘点一旦可行，应尽快以阶段 1 的最小 ACNH 真正执行路径验证所有静态推断。可逆测试岛与正式存档完全隔离。每个版本补丁应含预期原指令、生成后散列、可复现报告；未知服务、shader 或图形函数持续触发显式错误，而非默认成功。Mush8 的差分执行工具与 D2R 的存档故障注入/设备采样适合作为**方法**引入，不意味着导入其另一个宿主。[Mush8 verify](https://github.com/c22dev/mush8/blob/975040ba341efb99c5631292a0266ae26b28d960/crates/nxpatch/src/main.rs#L88-L114)、[D2R 验证工具索引](https://github.com/jhaizhou-ops/d2r-mobile/blob/53e7c5bb9ca3ea53e2160005be8fbe920cd9cb53/dm/verify/README.zh-CN.md)。

**硬停止条件：** 改写出现无法证明等价的不可支持指令/控制流；未来版本出现无可行解决办法的代码段重定位；必需系统服务依赖无法合理重现的 Nintendo 远端状态；NVN/shader 关键路径缺口在限时原型内呈系统性扩大且无可行修补路径；iOS **CPU 代码**签名、虚拟地址、设备内存/热量要求无法满足已选硬件；存档在断电/后台中断测试中可能不可恢复。现已确认的 3.0.0 RELR 全在 `.data`，GNU-only `DT_HASH` 缺口可作定点实现，均不属于已触发的硬停止条件。停止意味着暂停承诺和重估路线，不是静默用功能桩越过门禁。

## 时间盒与估算前提

当前没有 ACNH 运行轨迹、实际 NVN 命令覆盖和系统服务缺口，也未完成更新 RomFS 合并；因此**不报人月或成功概率**。建议先给阶段 0 剩余盘点与阶段 1 最小执行各设置一个**短期、可调整的时间盒**：阶段 0 聚焦 GNU-only patcher 校验、可达服务与 3.0.0 BKTR/shader 清单；阶段 1 只追求一个锁定版本的真实首帧及明确错误清单。时间盒结束按“完成/明确可修缺口/需换底座/停止”复盘，并依据实际未实现 SVC/IPC/NVN 数量、shader miss、存档语义与设备内存采样，再估 macOS 可玩纵切片和 iOS 工期。若先做 1.0.0，必须另列 3.0.0 版本迁移成本。多人通信、真 Switch 互通、Nintendo Online、旧岛迁移与 DLC 作为独立范围估算，不能埋在单机预算里。

**后续原型需要补证的关键未知。** x18/sysreg/SVC 线性编码候选的**可达**指令与改写拒绝项；update 3.0.0 的 BKTR 合并后 shader/资源清单、真实绑定/反射及覆盖；ACNH 使用的 NVN driver export/函数和系统 save/account/time/swkbd/网络**实际调用**；目标 Mac/iPhone 的 OS、内存和可接受功能范围。版本、模块与 Build ID、NPDM 权限、GNU-only 符号数、RELR/RELA 目标段及 12 个 shader 编译样本已有静态/工具链证据；运行行为仍需受控 ACNH 轨迹，不可由三个项目经验代替。
